Fix: These bodies include links without <inertial>, for which each engine substitutes its own default mass (the links are listed under file.inertial). Add explicit <inertial> blocks.
Fix: PyBullet's loadURDF ignores URDF inertia tensors by default and recomputes them from collision shapes. Pass flags=URDF_USE_INERTIA_FROM_FILE (simcompat: -b pybullet:inertia_from_file=1).
Also explains: dynamics.mass_matrix (mujoco, pybullet), dynamics.gravity (mujoco, pybullet), dynamics.coriolis (mujoco, pybullet), rollout.rigid (pybullet), rollout.passive (pybullet)
What does inertia.clusters check?
Each engine's mass properties match the file, for everything each joint moves. For every movable joint, simcompat compares the composite mass, center of mass and inertia tensor of all links that joint moves, in the world frame at q = 0. Fixed-joint children are merged first, so engines that fuse static bodies (MuJoCo) compare fairly with engines that keep them (PyBullet). Typical causes: links without <inertial> (each engine substitutes a different default); links with zero mass but non-zero inertia (MuJoCo drops that inertia); engines that recompute inertia from collision geometry (PyBullet without URDF_USE_INERTIA_FROM_FILE); a lost inertial-frame rotation. Fix: give every moving link an explicit, physical <inertial>, and use the engine's "inertia from file" option where it has one.

2. An engine reads joint damping or friction but does not simulate it

FAILrollout.passive_effectpybullet
SeverityEngineJoint / linkFinding
FAILpybulletdeclared <dynamics friction> has NO effect on the motion (read but not simulated) on j1
Fix: pybullet stores <dynamics friction> (getJointInfo) but loadURDF does not simulate it. Workaround: a VELOCITY_CONTROL motor with targetVelocity=0 and force=friction on each joint.
What does rollout.passive_effect check?
Turning each engine's own damping (or friction) handling on changes the motion. This compares every simulator with itself, so it needs no cross-engine tolerance. A parameter that is stored but has no effect is silently ignored: the robot is less damped than its file says. (Observed: PyBullet stores <dynamics friction> but does not simulate it.)

Also explains: rollout.rigid (pinocchio)
What does file.inertial check?
Every link that a joint moves declares an <inertial> block. The URDF specification says a link without <inertial> has zero mass, but engines disagree: MuJoCo derives mass from the collision geometry, PyBullet assigns 1 kg and Pinocchio uses 0. The robot therefore weighs something different in each engine. Fix: give every moving link an explicit <inertial> (even a tiny one for sensor frames).

4. Mimic couplings are enforced by some engines and ignored by others

Fix: pybullet.loadURDF does not create <mimic> couplings; add them yourself, e.g. createConstraint(..., JOINT_GEAR, ...) with gearRatio = -multiplier.
What does import.mimic check?
How each engine implements <mimic> couplings. MuJoCo turns them into equality constraints; PyBullet's loadURDF and Pinocchio (by default) leave the joint independent, so grippers and hands move differently. A simulator that drops the coupling is a WARN; the dynamics reference computing unconstrained dynamics is expected (INFO).

FilePhysically valid inertia file.inertia_validity● file
Inertia tensors are positive semi-definite and satisfy the triangle inequality. Engines disagree on what to do with an impossible tensor (not positive semi-definite, or principal moments that violate A + B >= C): MuJoCo refuses to load the model, even for a static link; PyBullet (with inertia from file) silently sets that link's inertia to zero; Pinocchio keeps the tensor. A tensor exactly on the edge (A + B = C, a flat or thin body) can tip either way after rounding. A link with zero mass but non-zero inertia is dropped by MuJoCo and kept by the others. Fix: correct the tensor (CAD exports often round it badly), or check it with `-b mujoco:balanceinertia=true`.

No joint range that engines interpret differently. Two cases are ambiguous. Engines expose the joints in the same order. Policies and controllers index joints by position.
